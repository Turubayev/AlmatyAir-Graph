# Доработка и доказательства готовности

Дата: 2026-10-09.

## Реализовано

Убраны двустороннее заполнение погодной истории и медиана PM по всему периоду. Разделение обучения/калибровки исключает пересечение 48-часовых целевых окон. Калибровка датчиков в train.py использует только период обучения (внешний co-location без time требует проверки дат). Добавлен ForecastArchive: время публикации, уникальные ключи, покрытие станций/горизонтов; табличные и GNN признаки используют прогноз из архива, включая агрегаты окна. API показывает происхождение старых весов.

## Аналог и применённый подход

[AirFormer](https://github.com/yoshall/AirFormer)

Взята идея проверяемого пространственно-временного прогноза и отделения training/validation/test; AirFormer не установлен. Архив issued forecast реализован непосредственно в текущем GNN/LightGBM конвейере.

## Запуск и проверка

```bash
python -m pytest -q
python scripts/train.py --data your_data.csv --stations your_stations.csv --train-end 2023-07-01 --val-end 2024-07-01 --weather-archive issued_weather.csv --out models/new --results results/new --no-stgnn
```

Регрессионные тесты: `python -m pytest -q`. Локальная среда проверки: Windows, Python 3.12. CI проверяет отдельную чистую среду.

## Что требуется для оценки 10/10

Переобучить веса после исправления утечек; старые веса и benchmark сохранены только для воспроизведения. Проверить реальный PM2.5 и архив выпущенных прогнозов на независимом сезоне; сравнить с persistence и CAMS, оценить интервалы и эпизоды. Формат issued_weather: issue_time,issued_at,valid_time,station_id,temp,rh,wind_speed,wind_dir,blh. Время в одной зоне, issued_at <= issue_time, все часы 1–48 присутствуют. Без --weather-archive режим reanalysis_plus_noise_research_only; это не эксплуатационная проверка.

Инженерные тесты подтверждают поведение кода; они не измеряют клиническую, гидрологическую или коммерческую точность. Метрики на синтетике нельзя переносить на реальные данные. Оценка 10/10 сейчас не заявляется.
